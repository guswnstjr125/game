## 2. 구현 전 선행 조건

현재 main `e8d0acb`에는 PR #112의 1~2층 이벤트·휴식 맵 연결까지 있다. 저장·이어하기·타이틀/일시정지 연결과 18노드 회귀 검증은 PR #113~#117에 분리되어 있으며, 감사 시점에는 병합되지 않았다. 이 PR들의 테스트 결과는 main에 반영된 완료 상태로 계산하지 않는다.

1. #113~#117의 병합 여부와 Windows Unity QA 결과를 확인하고, 1단계 D-66 경로를 고정한다.
2. 정본 xlsx에서 3~5층 데이터와 카드·보스·유물·이벤트 풀을 내보내고 `38`의 매핑 및 생성 에셋 대조를 통과시킨다.
3. D-79의 보스 행동 데이터가 Core 실행기에서 실제로 해석되는지 확인한다. 데이터 Note를 읽지 못하는 행동은 보스 구현 완료로 세지 않는다.
4. 진행 저장은 main의 D-67 저장 흐름을 재사용한다. D-84 휴식 저장 및 D-85 진행 슬롯 교체는 현재 열린 PR #113·#115에 포함된 결정이므로, 해당 PR이 병합된 뒤에만 main 확정 규칙으로 취급한다. 2단계에서 추가되는 영구 메타 값은 `14` MetaSave와 `26` 필드로 이어서 저장한다.

### 4.2 결정이 필요한 시뮬레이터 설계 선택

현재 D-04의 런 클리어율 30~45%는 바꾸지 않는다. 자동 측정 수단에는 아래 선택이 남아 있으며 이번 문서에서 D로 확정하지 않는다.

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 전체 런 시뮬레이터 (추천) | 기존 전투 시뮬레이터를 호출하는 런 조정기가 맵·보상·이벤트·휴식·상점·융합·정산을 실제 규칙대로 진행. 결과는 클래스/메타 기준별 런 클리어율·층 도달률·HP 손실로 보고 | D-04가 요구하는 실제 런 단위 측정이며 전투 승률의 독립 곱을 쓰지 않음 | 런 밖 선택 정책과 시뮬레이션 입력/출력 계약을 먼저 정해야 함 |
| B. 수동 플레이만 사용 | #28의 10런 기록과 Windows 플레이를 밸런스 판정에 사용 | 구현 비용 없음, 실제 플레이 의사결정 반영 | 많은 빌드/시드를 반복해 30~45% 목표를 통계적으로 비교하기 어려움 |
| C. 전투별 승률을 조합 | 개별 전투 승률로 런 승률을 추정 | 작성이 단순함 | D-04·`16` §8에 금지된 독립곱 추정이므로 채택 불가 |

추천 선택은 A다. 구현 전 별도 D 결정에서 최소한 다음을 고정해야 한다: 봇의 카드/공격/방어/희생/융합 결정, 이벤트·휴식·상점 선택 정책, 시작 클래스 및 메타 풀 상태별 보고 단위, 반복 시드 수와 목표 판정 방법. 결정 전에는 시뮬레이터를 30~45% 자동 Go/No-Go 근거로 사용하지 않는다.

### 4.3 확정 설계와 제안의 경계

- **확정**: 5×9 단일 경로, 2~5층 상점 위치, 클래스 덱/보정/언락, 카드·적·보스·유물·이벤트 수치, Lv2 융합, 메타 보상·업적, 5층 승리 조건, D-80 검증 등급, 2단계 UI 분리, 연출·사운드 Should는 기존 D와 정본을 따른다.
- **제안**: §3의 이슈 크기·구현 DAG와 §4.2의 전체 런 시뮬레이터 옵션 A는 작업 순서/도구 설계 추천이다. 게임 규칙·수치·합격 기준을 변경하지 않으며 새 D 결정 전에는 확정 설계로 취급하지 않는다.
- **이번 변경에서 결정하지 않음**: MVP 범위 확대, 새 클래스 레벨 시스템, 적·보상·경제 수치 변경, 시뮬레이터 정책과 통계 판정. 카드 성장 구조는 기존 층 해금·메타 카드 풀 언락을 사용한다.

## 5. 구현 가능한 작업 목록

1. 1단계 #113~#117의 병합·QA 관문을 닫고 저장/런 상태 모델을 고정한다.
2. 3~5층 Encounter/Enemy/Boss 데이터를 Core 실행기와 연결하고 D-79 행동 검증을 추가한다.
3. `08`·`09`·`10` 정본 데이터에서 2단계 카드·몬스터·적·보스 에셋을 생성하고 미해결 ID를 0으로 만든다.
4. 5층 RunFlow, 노드 유형별 보상, 층 전환 및 정산을 하나의 저장 가능한 런 진행으로 연결한다.
5. Lv2 융합과 3층 성소 무료 융합 사용을 저장·복구 및 중복 방지와 함께 연결한다.
6. 유물·이벤트·상점·소모품·클래스 선택·메타 화면을 D-62의 별도 2단계 UI 작업으로 등록한다.
7. `32` 기존 Stage2 Must Pass를 구현 결과와 연결하고 45노드 완주·저장 재개·중복 지급을 자동/Unity 검증한다.
8. 런 클리어율 자동 측정 전에는 §4.2의 봇 결정과 통계 기준을 D로 확정한다. 그 전까지 수동 10런 기록과 실제 플레이를 별도 증거로 유지한다.
