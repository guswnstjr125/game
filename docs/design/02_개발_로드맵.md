## 1. 현재 목표

```
1~5층 전체 런 플레이 가능 (Vertical Slice)
```

구체적으로:
- 전투 가능
- 카드 사용 가능
- 적 AI 동작
- 상태이상 적용
- 희생 가능
- 소환 가능
- 보스 패턴 동작
- 웨이브 진행 가능
- 승패 가능

### MVP 범위 고정 (`03_MVP_전층_스펙.md` 정본)

- 맵: 층당 9노드 **단일 경로** (5층 = 45노드)
- 노드: Battle 4 / Event 2 / Elite 1 / Rest 1 / Boss 1
- Shop: 2층+ 노드6에서 Event와 **30% 옵션 치환**
- Treasure / Mimic: **Post-MVP** (MVP 미등장)
- 풀 버전 맵 분기 규칙은 `23_콘텐츠_설계.md`·`24_콘텐츠_런타임_상세.md`의 Post-MVP 절을 참조

## 3. 구현 순서 (반드시 준수)

순서가 뒤집히면 구조가 붕괴된다.

```
1.  전투 코어 (BattleAction, BattleContext)
2.  Queue 시스템 (QueueProcessor, Main/Trigger/Death Queue)
3.  Runtime 시스템 (RuntimeUnit, RuntimePlayer, RuntimeEnemy)
4.  카드 시스템 (CardData, RuntimeDeck, CardResolver)
5.  상태이상 시스템 (StatusSystem, RuntimeStatusEffect)
6.  AI 시스템 (EnemyAI, TargetSelector)
7.  희생 시스템 (SacrificeSystem)
8.  소환 시스템 (SummonSystem, RuntimeSummon)
9.  보스 시스템 (BossPatternAI, BossPhase)
10. Stage / Wave 시스템 (StageGenerator, WaveData)
11. Battle Simulator 구현
12. 자동 밸런싱 구현
```

## 4. 주차별 개발 일정 (Vertical Slice 기준)

### 1주차 — 전투 코어

```
BattleAction
QueueProcessor
RuntimeUnit
BattleManager
TurnManager
BattleContext
```

### 2주차 — 카드 시스템

```
CardData / CardRegistry
RuntimeDeck / RuntimeHand
Draw / Discard / Exhaust
CardResolver
```

### 3주차 — 상태이상 / AI / Targeting

```
RuntimeStatusEffect
StatusSystem (Burn, Poison, Weak, Vulnerable)
TargetSelector
EnemyAI (AggressiveAI, BossPatternAI)
```

### 4주차 — 희생 / 소환 / 보스

```
SacrificeSystem
FusionSystem (FusionCharge · 비용 · 판정 순서, 01 §7 D-03)
RuntimeSummon / SummonSystem
BossPhase / BossPattern
굶주림의 사제 패턴 구현
```

### 5주차 — Stage / Wave / 이벤트

```
StageGenerator
WaveData / EnemySpawn
EventData (MVP 4개)
Shop 치환 규칙(2층+ 노드6 Event 30%)
RewardTable
```

### 6주차 — Simulator / 밸런싱

```
BattleSimulator (BattleRunner, AIController, ResultCollector)
BalanceAnalyzer (OTK / 무한루프 탐지)
자동 밸런싱 루프
```
