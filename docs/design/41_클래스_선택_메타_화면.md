## 1. 화면 흐름

```
타이틀
 ├─ 새 런 ──→ 클래스 선택 ──[시작]──→ 런 시작 (`37` §1.1)
 │              └─[언락으로]──→ 메타 언락
 ├─ 이어하기
 ├─ 메타 언락 ──→ (언락 탭 / 업적 탭) ──[뒤로]──→ 타이틀
 ├─ 설정
 └─ 종료

결과 화면 ──[계속]──→ 타이틀 (메타 화폐·업적은 결과 화면에서 이미 지급, `37` §1.3)
```

- 메타 화폐는 런 중에 쓰지 않는다 (`26` §5). 그래서 메타 언락은 타이틀에서만 연다.
- 첫 실행(아무 언락도 없을 때) 타이틀의 "메타 언락" 버튼은 보이지만, 화폐가 0이면 언락 탭의 모든 [언락] 버튼이 비활성이다.

## 2. 클래스 선택 화면

### 2.1 구성

| 영역 | 내용 |
|---|---|
| 클래스 목록 (왼쪽) | 5칸: NEC · ELE · BEA · HOL · NEU (`29` §7 순서). 칸마다 클래스 이름, 대표 몬스터 그림(그 클래스 `*_MON_001` 필드 스프라이트, `39` §2), 상태 표시 |
| 미리보기 (오른쪽) | 선택한 클래스의 핵심 테마 한 줄(`29` §7), 시작 유물(이름·효과, `18`·D-06), 시작 덱 10장 목록(`18`), 난이도·보정(`18` §7) |
| 버튼 | [시작] (열린 클래스만 활성) · [언락으로] (잠긴 클래스를 골랐을 때만 보임) · [뒤로] |

### 2.2 클래스 상태

| 상태 | 조건 | 표시 | [시작] |
|---|---|---|---|
| 열림 | NEC, 또는 `Meta_Unlock`에서 구매함 | 컬러 그림 | 활성 |
| 구매 가능 | 언락 조건을 채웠고 아직 구매하지 않음 | 회색 그림 + "Soul N으로 언락" | 비활성, [언락으로] 표시 |
| 잠김 | 언락 조건을 못 채움 | 검은 실루엣 + 조건 문구 (§4.2) | 비활성, [언락으로] 표시 |

- NEC는 처음부터 열려 있다 (`Meta_Unlock`에 행이 없음).
- 처음 선택 위치는 마지막으로 시작한 클래스다. 기록이 없으면 NEC.
- 미리보기는 잠긴 클래스도 모두 보여 준다. 무엇을 얻는지 알아야 언락을 고를 수 있기 때문이다.

### 2.3 시작 정보 (`18`)

| 클래스 | 시작 유물 | 보정 |
|---|---|---|
| NEC | `REL_BLOOD_CHALICE` 피의 잔 | 기본 |
| ELE | `REL_CORRUPT_CHALICE` 타락한 성배 | 시작 Crystal +1 |
| BEA | `REL_ABYSS_HEART` 심연의 심장 | 기본 |
| HOL | `REL_FORBIDDEN_CANDLE` 금단의 촛불 | 시작 HP +5 |
| NEU | `REL_CURSED_SKULL` 저주받은 두개골 | 시작 골드 +40 |

시작 유물은 고르지 않는다 (D-06). 미리보기는 정보만 보여 준다.

## 3. 메타 언락 화면

### 3.1 공통

| 영역 | 내용 |
|---|---|
| 위 | 보유 화폐: 타락의 영혼(`META_SOUL`)·심연 인장(`META_SIGIL`) 숫자 |
| 탭 | [언락] · [업적] |
| 버튼 | [뒤로] (이전 화면: 타이틀 또는 클래스 선택) |

### 3.2 언락 탭

`Meta_Unlock` 행 중 MVP에서 쓰는 **6개**를 이 순서로 보여 준다. `UNL_RELIC_BOSS`는 Post-MVP라 보이지 않는다 (§5, D-53).

| 순서 | Unlock_ID | 이름 | 비용 | 조건 (`Condition`) |
|---|---|---|---|---|
| 1 | `UNL_CLASS_ELE` | 정령 클래스 | Soul 80 | 없음 |
| 2 | `UNL_CLASS_BEA` | 야수 클래스 | Soul 120 | 2층 클리어 1회 (`ClearFloor2Once`) |
| 3 | `UNL_CLASS_HOL` | 신성 클래스 | Soul 150 | 3층 클리어 1회 (`ClearFloor3Once`) |
| 4 | `UNL_CLASS_NEU` | 무속성 클래스 | Soul 150 | 4층 클리어 1회 (`ClearFloor4Once`) |
| 5 | `UNL_CARD_RARE_T1` | Rare 카드 | Soul 100 | 1층 클리어 3회 (`ClearFloor1_x3`) |
| 6 | `UNL_CARD_LEG` | Legendary 카드 | Soul 220 + Sigil 2 | 4층 클리어 1회 (`ClearFloor4`) |

행마다 이름, 효과 한 줄(§5), 비용, 조건과 진행도(예: "1층 클리어 1/3"), 버튼을 둔다.

| 버튼 상태 | 조건 |
|---|---|
| [언락] 활성 | 조건 충족 + 화폐 충분 |
| [언락] 비활성 + "화폐 부족" | 조건 충족, 화폐 부족 |
| 잠김 + 조건 문구 | 조건 미충족 |
| "언락됨" | 구매함 |

- [언락]을 누르면 확인 창("Soul 80을 써서 정령 클래스를 엽니다") → 확인하면 화폐를 빼고 즉시 `meta.json`에 저장한다 (`26` §5).
- 언락은 다음 런부터 적용된다 (`26` §5). 런 저장이 있는 동안 산 언락은 그 런에 영향을 주지 않는다.
- 되돌리기(환불)는 없다.

### 3.3 업적 탭

`Meta_Achievement` 12개를 표 순서대로 보여 준다.

| 열 | 내용 |
|---|---|
| 이름·조건 | §4.3 문구 |
| 보상 | Soul·Sigil |
| 상태 | 달성(날짜) / 진행도(누적형만, 예: "희생 32/50") / 미달성 |

- 업적은 한 번만 달성하고, 보상은 달성한 런의 결과 화면에서 지급한다 (`37` §1.3).
- 잠긴(숨긴) 업적은 없다. 12개 모두 처음부터 조건이 보인다.

## 4. 판정 규칙 (D-53)

### 4.1 기록하는 누적 값

`meta.json`(`14` MetaSaveDTO)에 `MetaStats`를 더한다. 런이 끝날 때(승리·패배·포기) 그 런의 값을 더한다.

| 필드 | 타입 | 뜻 |
|---|---|---|
| `FloorClearCount` | int[5] | 층별로 보스를 처치한 런 수 (1층 클리어 = 1층 보스 처치) |
| `TotalSacrifice` | int | 희생 횟수 누적 |
| `TotalFusion` | int | 융합 횟수 누적 |
| `TotalExecuteKill` | int | Execute 효과로 처치한 적 수 누적 |
| `TotalBurnDamage` | int | 아군이 건 Burn 틱이 적에게 준 피해 누적 |
| `TotalPoisonDamage` | int | 아군이 건 Poison 틱이 적에게 준 피해 누적 |
| `ClassWins` | Dictionary<string,int> | 클래스별 런 승리 수 |
| `LastClass` | string | 마지막으로 시작한 클래스 (§2.2) |

### 4.2 언락 조건

| Condition | 판정 |
|---|---|
| `None` | 항상 충족 |
| `ClearFloorNOnce`, `ClearFloorN` | `FloorClearCount[N] ≥ 1` (두 표기는 같은 뜻이다) |
| `ClearFloor1_x3` | `FloorClearCount[1] ≥ 3` |

### 4.3 업적 조건

| Achievement_ID | 화면 문구 | 판정 |
|---|---|---|
| `ACH_CLEAR_F1` | 1층 클리어 | 1층 보스 처치 (처음 1회) |
| `ACH_CLEAR_F5` | 5층 클리어 | 5층 보스 처치 = 런 승리 |
| `ACH_NO_DEATH_F2` | 2층까지 아군 무사망 | 한 런에서 2층 보스를 처치할 때까지, 희생이 아닌 아군 몬스터 사망 0. 해골 토큰(`NEC_ACT_002`)의 사망은 세지 않는다 |
| `ACH_SACRIFICE_50` | 누적 희생 50회 | `TotalSacrifice ≥ 50` |
| `ACH_FUSION_30` | 누적 융합 30회 | `TotalFusion ≥ 30` |
| `ACH_EXECUTE_100` | 누적 처형 100회 | `TotalExecuteKill ≥ 100` |
| `ACH_BURN_999` | 누적 Burn 피해 999 | `TotalBurnDamage ≥ 999` |
| `ACH_POISON_999` | 누적 Poison 피해 999 | `TotalPoisonDamage ≥ 999` |
| `ACH_BOSS_1TURN` | 보스를 첫 턴에 처치 | 보스 전투의 첫 플레이어 턴이 끝나기 전에 보스 처치 (어느 층이든) |
| `ACH_ZERO_COST_WIN` | 0 Crystal 카드로 승리 | 런 승리 + 그 런에서 사용한 카드의 60% 이상이 Crystal 0 카드 |
| `ACH_NO_RELIC_WIN` | 유물을 모으지 않고 승리 | 런 승리 + 시작 유물·보스 유물 외 유물(엘리트·이벤트·상점) 0개 |
| `ACH_ALL_CLASS_WIN` | 다섯 클래스로 승리 | `ClassWins`의 NEC·ELE·BEA·HOL·NEU가 모두 1 이상 |

- 누적형은 런 중에 조건을 넘으면 그 런의 결과 화면에서 달성으로 보여 준다.
- `ACH_NO_RELIC_WIN`은 보스 유물을 빼고 센다. 보스 보상 유물은 자동 지급이고 거절할 수 없기 때문이다 (`37` §2.3).

## 5. 카드·유물 풀 언락의 효과 (D-53)

| Unlock_ID | 효과 |
|---|---|
| `UNL_CARD_RARE_T1` | 언락 전: 카드 보상·이벤트 카드(`GrantCard`)에서 Rare 희귀도 후보가 0장인 것으로 본다 → D-49대로 Rare 확률을 빼고 재정규화. 언락 후: Rare 카드가 나온다. MVP에서 "1단계(T1)"는 Rare 카드 전체다 (나눌 Tier 2는 Post-MVP) |
| `UNL_CARD_LEG` | 같은 방식으로 Legendary 희귀도를 연다 (MVP Legendary 카드는 `HOL` 1장) |
| `UNL_RELIC_BOSS` | **Post-MVP**. 보스 보상은 층마다 고정이라(D-16) "풀 확장"이 바꿀 대상이 없다. Excel 행은 남기고 화면·판정에서 뺀다 |

- **1단계 빌드에는 메타가 없으므로 언락 판정을 하지 않는다.** Rare·Legendary는 처음부터 열린 것으로 본다 (지금 1단계 규칙 그대로).
- 시작 덱에 들어 있는 카드는 언락과 관계없이 쓴다. 언락은 보상으로 새로 얻는 카드에만 적용한다.
- 밸런스 측정(#28)과 런 클리어율 목표(30~45%, D-04)는 **Rare·Legendary를 연 상태**를 기준으로 본다. 언락 전 런은 진행 곡선의 일부다.

## 7. 구현 순서 (2단계)

1. `MetaStats` 저장 필드와 런 종료 누적 (`14`)
2. 언락 조건·업적 판정 (§4, 순수 로직이라 `DarkLegion.Core` EditMode 테스트)
3. 카드 풀 언락의 보상 반영 (§5, D-49 재정규화 재사용)
4. 클래스 선택 화면 → 메타 언락 화면
5. 검증: `32` META-01~03 (§8)
