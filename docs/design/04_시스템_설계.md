## 1. 전투 시스템 개요

플레이어는 직접 공격하지 않는다.
몬스터를 소환하고 명령하여 전투를 수행한다.

---

## 2. 필드 구조

```
아군:  [Front] [Middle] [Back]                         (3)
적군:  [Front] [Middle] [Back] [Extra1] [Extra2]       (5)
```

적 Extra 2칸은 소환·다수 스폰용이다. 기본 타격 우선순위는 Front → Middle → Back → Player 이고, Extra는 앞 3칸이 찬 뒤의 오버플로 슬롯이다. 정본 배치·교체 규칙은 `09_BattleField_슬롯_상세설계.md`.

### 공격 우선순위

```
Front → Middle → Back → Player
```

### 위치 보너스

| 위치 | 효과 |
|---|---|
| Front | 방어 보너스 |
| Back | 스킬 보너스 |

## 3. 턴 구조

```
Turn Start
→ 상태이상 처리 (TurnStart 타이밍)
→ Draw
→ Main Phase        ← 플레이어 입력 허용 구간
→ Command Phase
→ Resolve Phase     ← Queue Flush
→ Death Check       ← Death Queue Flush
→ Enemy Phase
→ Turn End          ← 상태이상 처리 (TurnEnd 타이밍)
```

> **주의**: Main Phase 이외 구간에서 플레이어 입력 금지.

### 리졸브 순서

```
아군 Front → 아군 Middle → 아군 Back
→ 적 Front → 적 Middle → 적 Back
```

### 메인 페이즈 행동

- 몬스터 소환
- 스킬 사용
- 액션 사용
- 몬스터 희생
- 위치 변경

### 커맨드 페이즈

각 몬스터 턴당 1행동: 공격 / 방어 / 스킬

## 4. 카드 시스템

### 기본 규칙

| 항목 | 규칙 |
|---|---|
| 시작 덱 | 10장 |
| 시작 패 | 5장 |
| 턴 종료 | 패 전체 버림 (Discard) |
| 덱 비율 | 시작 몬스터 비율 **60%** (10장 중 6장). 후반 목표 **80%** |

### 카드 타입

| 타입 | 설명 | 특이사항 |
|---|---|---|
| Monster | 몬스터 소환. 최대 필드 3마리 | 몬스터 사망 시 카드 Discard |
| Skill | 유틸 / 콤보 / 지원 효과 | — |
| Action | 강력한 즉발 효과 | 일부 임시 카드 / 일부 미사용 시 소멸 |

### 덱 관리 구조

```
DrawPile → Draw → Hand → Use → DiscardPile
                              ↘ Exhaust → ExhaustPile
```

### 카드 실행 흐름

```
카드 선택
→ Cost 확인
→ Target 선택
→ BattleAction 생성 (카드는 직접 실행하지 않음)
→ Queue 등록
→ 카드 이동 (Discard or Exhaust)
→ Resolve
```

### Effect 조합 구조

카드는 `List<EffectDefinition>` 조합으로 동작을 정의한다.

```
CardData
 └── List<EffectDefinition>
       예) Blood Slash
           - Damage 8
           - ApplyBleed 2
           - LoseHP 2
```

## 6. 희생 시스템

### 철학

희생은 비용이다. 카드 Resolve 이전에 처리된다.

### 희생 흐름

```
PlayRequest
→ 희생 대상 선택
→ Sacrifice Validation
→ Target Lock
→ Sacrifice Reservation (즉시 제거 금지)
→ Card Resolve
→ Death Queue 등록
→ 보상 지급 (Crystal / Soul / Blood / Bone)
→ OnDeath Trigger
→ 제거
```

### 희생 보상

| 몬스터 레벨 | Crystal 획득 |
|---|---|
| Lv1 희생 | +1 |
| Lv2 희생 | +2 |
| Lv3 희생 | +3 |

> 상세 경제 수치는 [16_밸런스_규칙.md] 참조.

## 7. 융합 시스템

### 기본 규칙

- 노드 3·6·9 클리어마다 융합 충전 +1 (최대 3). 전투 중 손패 2장으로 융합 (`01` D-03)
- 같은 레벨 몬스터 카드 2장 소멸 → 상위 레벨 생성
- 카드 자체가 소멸됨 (DeadCard → ExhaustPile 아님)

### 몬스터 레벨 구조

| 레벨 | 설명 | 생성 방법 |
|---|---|---|
| Lv1 | 기본 몬스터 | 소환 |
| Lv2 | Lv1 융합 | Lv1 × 2 |
| Lv3 | Lv2 융합 | Lv2 × 2 |
| Lv4 | 전설급 | 특수 조건 |

### 융합 결과 비율

| 방식 | 비율 |
|---|---|
| 고정 레시피 | 30% |
| 랜덤 융합 | 70% |

> 위 비율은 **콘텐츠 구성 목표**(조합 중 고정 레시피 비중)이며 판정 확률이 아니다. 시점·비용·판정 순서 정본: `01_MVP_설계_동결_선언.md` §7 **D-03**

### 무속성(NEU) 융합 규칙

```
무속성 + 클래스 몬스터
→ 50% 클래스 상위 레벨
→ 50% 무속성 상위 레벨
```

## 8. 상태이상 시스템

상태이상은 독립 시스템으로 관리. RuntimeStatusEffect로 구현.

### 상태이상 목록 및 처리 시점

| 상태 | 효과 | 처리 시점 | 중첩 |
|---|---|---|---|
| Burn | 턴 종료 피해 (스택당 1) | TurnEnd | 가능, 최대 20 |
| Poison | 지속 피해 (스택당 1, 전투 중 유지) | TurnEnd | 가능, 최대 20 (`01` D-08) |
| Weak | 공격력 -25% | Damage 계산 시 | 2턴 |
| Vulnerable | 받는 피해 +25% | Damage 계산 시 | 2턴 |
| Shield | 피해 흡수 (턴 종료 전량 소멸) | Damage 직전 | — |
| Taunt | 적 공격 강제 (패시브) | 상시 | — |
| Bind | 행동 불가 (공격/스킬 봉쇄, 희생은 가능) | 행동 시작 시 | N턴 |
| Stun | 1턴 완전 무력화 | 턴 시작 시 | 1턴 |

### 상태이상 계산 순서

```
기본피해 × 치명 × Weak
→ DEF 차감
→ × Vulnerable
→ 내림, 최소 1 (공격 피해)
→ Shield → HP
```

정본: `01_MVP_설계_동결_선언.md` §7 **D-01**, `06_전투_코어_상세설계.md` §11

> 상세 수치 기준은 [16_밸런스_규칙.md] 참조.

## 9. AI 시스템

### 핵심 철학

AI는 행동을 직접 실행하지 않는다.  
오직 Intent 생성 → Queue 요청만 수행.  
복잡한 전략 AI 금지 (MVP 기준 우선순위 AI 사용).

### AI 행동 흐름

```
행동 가능 여부 검사
→ 상태이상 확인 (Stun / Bind)
→ 우선순위 판단
→ 행동 선택
→ Target 선택
→ Queue 등록
```

> Queue 처리 중 AI 재계산 금지.

### AI 타입

| AI 타입 | 설명 | 주요 사용 적 |
|---|---|---|
| AggressiveAI | 공격 우선, Front 우선, 압박 중심 | 야수, 구울, 악마 |
| DefensiveAI | 방어 우선, Taunt 사용, 생존 중심 | Tank 계열 |
| ControlAI | 상태이상 우선 (Burn, Weak, Bind) | 마법사, 사제 계열 |
| SummonAI | 하수인 소환 우선, 후열 유지 | 소환사 계열 |
| BossPatternAI | 고정 패턴 순환, HP 기반 페이즈 전환 | 보스 전용 |

### 타겟팅 규칙

| 타입 | 설명 |
|---|---|
| FrontEnemy | 전열 우선 |
| LowestHp | 체력 최저 |
| HighestAttack | 공격력 최고 |
| RandomEnemy | 랜덤 |
| AllEnemies | 전체 |
| Self | 자신 |
| AllAllies | 아군 전체 |
| Corpse | 시체 대상 |
| SacrificeTarget | 희생 대상 |

> **핵심 규칙**: Target은 실행 시점에 재검증한다. (Queue 처리 중 대상 사망 가능)

## 10. 보스 패턴 시스템

### 철학

보스는 전투 퍼즐이다. 패턴 이해 없이 클리어 불가 설계.

### 보스 패턴 구조

```csharp
BossPhase {
    float HpThreshold;       // 페이즈 전환 HP 비율
    List<BossPattern> Patterns;
}

BossPattern {
    int Turn;                // 몇 번째 턴에 사용
    SkillData Skill;
}
```

### MVP 보스: 굶주림의 사제

| 페이즈 | 진입 조건 | 행동 패턴 |
|---|---|---|
| Phase 1 | 개시 | 단일 공격 / Weak 부여 |
| Phase 2 | HP 50% | 하수인 소환 / 흡혈 / 광역 공격 |
| Phase 3 | HP 20% | 광폭화 / 2회 행동 |

## 11. Stage / Wave 시스템

### 구조

```
Floor
 └── Stage
       └── Wave
             └── EnemySpawn
```

### MultiWave 흐름

```
Wave 1
→ Wave 2 (있으면, 중간 보상 없음)
→ 노드의 모든 Wave 클리어 후 보상 1회
```

Wave 사이에는 카드·골드·유물 보상이 없다. 보상은 노드 승리 때 한 번이다 (`03_MVP_전층_스펙.md` §2·§8).

### Wave 간 규칙 (MVP 확정)

동일 스테이지 내 **Wave 2+** 진입 시:

| 항목 | 규칙 |
|------|------|
| 상태이상 (아군/적) | **유지** |
| 아군 몬스터 필드 | **유지** (HP·상태 그대로) |
| 소환수(토큰) | **제거** |
| Crystal | **턴 시작 규칙대로 전량 리셋** (이월 없음) |
| 패 | **전량 Discard 후 기본 드로우 5** |
| 유물·덱 구성 | 유지 |

> 층/스테이지를 **완전히 벗어날 때**만 전투 전체 초기화.

### ThreatValue 시스템

웨이브 난이도 자동 계산용 수치.

```
Threat = HP × 0.4 + ATK × 1.2 + DEF × 0.8 + 스킬 가중치
```

등급은 서로 겹친다. 구분 키는 Excel `Enemies_Master`의 역할(일반 / ELT / BOS)이고, Threat 숫자는 그 행의 실측이다.

| 구분 | Threat (Excel) |
|---|---|
| 일반 | **8~18** (1층 일반은 **8~9**) |
| 엘리트 | **11~21** |
| 보스 | **22~48** |

## 12. 이벤트 시스템

### 핵심 원칙

모든 이벤트는 리스크 ↔ 보상 구조.

### MVP 이벤트 목록

| 이벤트명 | 설명 |
|---|---|
| 악마 계약 | 강력한 보상, 저주 부여 |
| 피의 제단 | HP 소모 → 카드 강화 |
| 저주 상자 | 고보상 + 저주 위험 |
| 영혼 감옥 | 갇힌 영혼 해방 → 보상 or 적 등장 |
| 방랑 상인 | 골드 또는 HP로 카드 |
| 잊힌 제단 | 회복 또는 희생 후 강화 |
| 어둠의 내기 | 50% 보상 / 50% 손실 |
| 묘지의 속삭임 | 저주와 Rare, 또는 소량 회복 |

상세·층별 가중치는 `23_콘텐츠_설계.md`와 `06_콘텐츠_마스터.xlsx` Events_MVP (8종, `01` D-10).
