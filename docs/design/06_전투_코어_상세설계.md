## 1. 개요

본 문서는 전투 시스템의 핵심 Runtime 구조를 구현 수준으로 정의한다.

모든 구현자는 아래 **핵심 원칙 5가지**를 최우선으로 준수해야 한다.

---

## 2. 핵심 원칙 (절대 규칙)

### 2.1 모든 전투 변화는 Action 기반

전투 중 발생하는 모든 상태 변화는 반드시 `BattleAction`을 통해 처리한다.

```csharp
// ✅ 허용
Queue.Enqueue(new DamageAction(...));

// ❌ 금지
target.CurrentHP -= 5;
```

---

### 2.2 즉시 실행 금지

모든 이벤트는 Queue에 등록 후 순차 처리한다.

```
카드 사용
→ BattleAction 생성
→ Main Queue 등록
→ QueueProcessor 실행
→ (Main 1건 후) Death Queue Flush
→ Trigger Queue Flush
```

---

### 2.3 Animation은 Presentation Only

애니메이션은 전투 로직에 영향을 주지 않는다.

```
로직 실행
→ 상태 확정
→ View 갱신
→ Animation 재생
```

Animation Event 기반 게임 로직 **금지**.

---

### 2.4 Runtime과 Data 분리

ScriptableObject(CardData, EnemyData 등)는 정적 데이터만 보유한다.
전투 중 변경되는 값은 Runtime 객체에서만 관리한다.

```
CardData (정적) → RuntimeCard (동적)
EnemyData (정적) → RuntimeEnemy (동적)
```

---

### 2.5 Death 즉시 제거 금지

HP ≤ 0 감지 시 즉시 제거 **금지**.
반드시 `IsDead = true` 설정 후 Death Queue를 통해 처리한다.

```
HP <= 0 감지
→ IsDead = true
→ Death Queue 등록
→ 현재 Queue Flush 완료 대기
→ DeathAction 실행
→ OnDeath Trigger
→ Drop 처리
→ Battlefield 제거
```

---

## 4. RuntimeUnit

### 4.1 목적

전투에 존재하는 모든 유닛(플레이어 / 적 / 소환수)의 공통 부모 클래스.

### 4.2 클래스 구조

```csharp
public abstract class RuntimeUnit
{
    public string UnitId;           // 전투 내 고유 식별자 (런타임 생성)
    public string DataId;           // 참조 DataId (CardData.Id, EnemyData.Id 등)

    public TeamType Team;           // Player / Enemy / Neutral

    // --- 스탯 ---
    public RuntimeStat MaxHP;
    public RuntimeStat Attack;
    public RuntimeStat Defense;

    // --- 현재 상태 ---
    public int CurrentHP;
    public int Shield;              // 턴 종료 시 전량 소멸

    // --- 플래그 ---
    public bool IsDead;
    public bool IsTargetable;
    public RuntimeBattleFlags Flags;

    // --- 상태이상 ---
    public RuntimeStatusContainer StatusContainer;

    // --- 태그 (AI / Targeting 판별용) ---
    public List<UnitTag> Tags;      // Tank, Summoner, Boss 등
}
```

> `IsDead = true`이면 Death Queue에 등록된 것으로 간주한다. Battlefield 실제 제거 전까지 슬롯을 유지한다.

## 5. RuntimeStat 시스템

### 5.1 목적

모든 수치 계산의 일관성 유지. 버프/디버프를 Modifier로 관리하여 원본 보존.

### 5.2 구조

```csharp
public class RuntimeStat
{
    public int BaseValue;               // 원본 수치 (ScriptableObject 참조값)
    public int AdditiveModifier;        // 버프/디버프 합산값 (+n, -n)
    public float MultiplicativeModifier = 1f; // 배율 (기본 1.0)

    public int FinalValue               // 읽기 전용 프로퍼티
        => Mathf.Max(0, Mathf.RoundToInt((BaseValue + AdditiveModifier) * MultiplicativeModifier));
}
```

### 5.3 계산 순서

```
(BaseValue + AdditiveModifier) × MultiplicativeModifier = FinalValue
```

**예시 — Weak 상태이상 적용:**
```
Attack.BaseValue = 10
Attack.AdditiveModifier = 0
Attack.MultiplicativeModifier = 0.75f  ← Weak 적용
FinalValue = (10 + 0) × 0.75 = 7
```

### 5.4 규칙

- 모든 전투 계산은 `FinalValue` 기준
- `BaseValue` 직접 수정은 영구 강화(Consume, 업그레이드)에만 허용
- 버프/디버프는 반드시 Modifier 사용

## 7. RuntimeBattleFlags

유닛별 특수 상태 플래그. `bool` 필드 집합.

```csharp
public class RuntimeBattleFlags
{
    public bool Invincible;       // 모든 피해 무효
    public bool Untargetable;     // 타겟 선택 불가
    public bool Silenced;         // 스킬 사용 불가
    public bool Frozen;           // 행동 불가 (Bind와 별도)
    public bool CannotHeal;       // 회복 불가
    public bool CannotDraw;       // 드로우 불가
}
```

> `Bind`는 상태이상(StatusEffect)으로 처리. `Frozen`은 플래그로 처리. 혼용 금지.

## 8. BattleAction 시스템

### 8.1 목적

전투의 모든 상태 변화를 캡슐화. Queue를 통해서만 실행.

### 8.2 기반 구조

```csharp
public abstract class BattleAction
{
    public RuntimeUnit Source;      // 행동 주체
    public RuntimeUnit Target;      // 행동 대상 (null = 전체/자신)
    public BattleActionPriority Priority;   // 처리 우선순위

    public abstract void Execute(BattleContext context);
}
```

### 8.3 Action 목록

| Action | 설명 |
|---|---|
| `DamageAction` | 피해 처리 (Shield → HP 순) |
| `HealAction` | 회복 처리 |
| `ApplyStatusAction` | 상태이상 부여 |
| `RemoveStatusAction` | 상태이상 제거 |
| `DrawCardAction` | 카드 드로우 |
| `DiscardCardAction` | 카드 버리기 |
| `ExhaustCardAction` | 카드 소멸 |
| `GainCrystalAction` | Crystal 획득 (희생 보상 포함) |
| `SummonAction` | 몬스터 소환 |
| `SacrificeAction` | 몬스터 희생 및 보상 처리 |
| `DeathAction` | 사망 처리 (Death Queue 전용) |
| `DestroyAction` | 즉시 제거 (환경 오브젝트 전용) |
| `MoveCardAction` | 카드 위치 이동 (Draw→Hand 등) |
| `SpawnRewardAction` | 전투 보상 스폰 (05_기술_아키텍처.md §16) |

### 8.4 BattleActionType (열거형)

```csharp
public enum BattleActionType
{
    Damage, Heal,
```

## 9. QueueProcessor

### 9.1 핵심 원칙

즉시 실행 절대 금지. 모든 Action은 Queue를 통해 처리.

### 9.2 Queue 종류 및 Flush 우선순위

등록 큐 (05_기술_아키텍처.md §4와 동일):

```
Main Queue      ← 일반 행동
Trigger Queue   ← 이벤트 Trigger
Death Queue     ← DeathAction 전용
```

**Flush 순서** (Main Action 1회 실행 직후):

```
1. Death Queue Flush
2. Trigger Queue Flush (Trigger 1건 실행마다 Death 재-Flush)
```

### 9.3 실행 루프

```csharp
public class QueueProcessor
{
    private Queue<BattleAction> mainQueue    = new();
    private Queue<BattleAction> triggerQueue = new();
    private Queue<BattleAction> deathQueue   = new();

    public void Process()
    {
        while (mainQueue.Count > 0)
        {
            BattleAction action = mainQueue.Dequeue();
            action.Execute(context);

            FlushDeathQueue();      // Death 최우선
            FlushTriggerQueue();    // Trigger 후처리
        }
        FlushDeathQueue();          // 최종 잔여 Death 정리
    }

    private void FlushDeathQueue()
    {
        while (deathQueue.Count > 0)
        {
            deathQueue.Dequeue().Execute(context);
        }
    }

    private void FlushTriggerQueue()
    {
        int iterations = 0;
        while (triggerQueue.Count > 0)
        {
            if (++iterations > MaxTriggerIterationsPerFlush)
            {
                EmergencyCleanup();
                return;
            }
            triggerQueue.Dequeue().Execute(context);
            FlushDeathQueue();
        }
    }
}
```

> `MaxTriggerDepth`(32)는 TriggerBus가 중첩 Trigger를 **Enqueue할 때** 깊이를 검사한다 (05_기술_아키텍처.md §5).

### 9.4 Nested Queue 규칙

Action 실행 중 새로운 Action 생성 가능. 단 즉시 실행 금지, 반드시 Queue 삽입.

```
Attack Action 실행
→ Burn Trigger 발생 → Trigger Queue 삽입
→ Bleed Trigger 발생 → Trigger Queue 삽입
→ Death 감지 → Death Queue 삽입
→ Death Queue Flush
→ Trigger Queue Flush
```

### 9.5 무한 루프 방지

05_기술_아키텍처.md §4 · `BalanceConfig`와 동일한 기본값:

```csharp
public const int MaxQueueCount                  = 500;
public const int MaxTriggerDepth                = 32;
public const int MaxTriggerIterationsPerFlush   = 20;
public const int MaxTurnCount                   = 30;
```

초과 시 → 전투 강제 종료 → 로그 출력 → EmergencyCleanup 실행.

## 10. TriggerBus

> **구현 정본**: [07_TriggerBus_상세설계.md](07_TriggerBus_상세설계.md) (구독·해제·유물/패시브·Priority 충돌)

### 10.1 목적

전투 이벤트 전달 시스템. Event는 상태를 직접 수정하지 않고, BattleAction 생성 후 Queue 삽입만 수행.

### 10.2 Trigger 이벤트 목록

| 이벤트 | 발생 시점 |
|---|---|
| `OnBattleStart` | 전투 시작 |
| `OnTurnStart` | 턴 시작 |
| `OnTurnEnd` | 턴 종료 |
| `OnCardPlayed` | 카드 사용 |
| `OnDamageTaken` | 피해 수신 |
| `OnDamageDealt` | 피해 적용 |
| `OnHeal` | 회복 |
| `OnDeath` | 사망 확정 |
| `OnSummon` | 소환 |
| `OnSacrifice` | 희생 |
| `OnStatusApplied` | 상태이상 부여 |
| `OnDraw` | 드로우 |

### 10.3 Trigger Priority (처리 순서)

```csharp
public enum TriggerPriority
{
    Before = 0,    // 사전 처리 (검사, 방어)
    On     = 1,    // 주 효과 처리
    After  = 2     // 사후 처리 (연쇄, 보상)
}
```

같은 Priority 내에서는 등록 순서대로 처리.

## 11. Damage Pipeline

### 11.1 전체 흐름

04_시스템_설계.md §8 · 05_기술_아키텍처.md §16과 동일: Weak/Vulnerable은 **Damage 계산**, Shield는 **Damage 직전**.

```
Damage Request
↓
Target Validate (IsDead / IsTargetable)
↓
Before Damage Trigger (방어, 무효화 등)
↓
치명 / Weak 계산
  ← 치명: 기본피해 × 1.5
  ← Weak: 공격 측(유닛) × 0.75
↓
DEF 차감 (대상 FinalDef, Front 보너스 포함; IgnoreDefense 시 0)
↓
Vulnerable 계산 (× 1.25)
↓
최종 피해 floor + Clamp (공격 피해 최소 1 / 상태이상 틱은 스택 값 그대로)
↓
Shield 감소 (남은 피해만 HP 적용; IgnoreShield 시 생략)
↓
HP 감소
↓
OnDamageTaken Trigger
↓
Death Check (HP <= 0 → IsDead = true → Death Queue 등록)
↓
After Damage Trigger
```

### 11.2 Shield 규칙

- Shield는 HP보다 먼저 감소
- `남은 피해 = max(0, Damage - Shield)`
- Shield는 턴 종료 시 전량 소멸 (Turn End 처리)

### 11.3 최소 피해

공격 피해(유닛 공격·카드 피해)는 DEF 차감 후 최소 1. Burn/Poison 틱은 스택 값 그대로 적용(DEF·Weak·Vulnerable 미적용). 음수 피해(회복 효과) 혼용 금지. 회복은 `HealAction`으로 별도 처리.

> 공식 정본: `01_MVP_설계_동결_선언.md` §7 **D-01**

### 11.4 치명타

치명타는 Modifier 단계에서 계산 (`MultiplicativeModifier` 활용).

```csharp
public class DamageAction : BattleAction
{
    public int BaseDamage;
    public bool IgnoreDefense;
    public bool IsCritical;         // true: ×1.5 (기본)
    public bool IgnoreShield;
}
```

## 12. Death 시스템

### 12.1 핵심 원칙

즉시 제거 절대 금지. 사망 유닛은 Death Queue에 등록 후 처리.

### 12.2 상세 흐름

```
HP <= 0 감지
↓
IsDead = true (IsTargetable = false)
↓
Death Queue 등록 (DeathAction)
↓
DeathAction.Execute()
  → OnDeath Trigger 발행
  → Deathrattle 효과 처리
  → Drop / 보상 처리
  → Battlefield 슬롯에서 제거
  → Graveyard 등록
```

### 12.3 사망 유닛 제한

`IsDead = true` 유닛은:
- 카드 사용 불가
- Action 생성 불가
- 타겟 불가 (`IsTargetable = false`)
- 단, `Deathrattle` 효과는 Death Queue 내에서 허용

## 13. TurnManager

### 13.1 턴 흐름

```
Battle Start
↓
[반복]
  Turn Start
    → 에너지(Crystal) 회복
    → 드로우 (기본 5장, 손패 상한 10 — D-30)
    → OnTurnStart Trigger
    → 상태이상 TurnStart Tick (Stun 등)
    → 적 Intent 확정, 행동 종류 아이콘 공개 (D-28)
  ↓
  Player Phase (Main Phase)
    → 카드 사용 / 희생 / 소환 / 위치 변경
  ↓
  Command Phase
    → 각 몬스터 공격(기본값, 대상 선택 가능) 또는 방어 선택 (D-27)
  ↓
  Resolve Phase
    → 방어 Shield 먼저 적용 → 공격 Queue Flush (아군 Front→Middle→Back 순)
  ↓
  Enemy Phase
    → 확정된 Intent 실행(대상은 이 시점에 선택) → Queue Flush (적 Front→Middle→Back 순)
  ↓
  Turn End
    → OnTurnEnd Trigger
    → 상태이상 TurnEnd Tick (Burn, Poison 등)
    → Shield 전량 소멸
    → 패 전체 Discard
    → Cleanup
↓
승패 판정 → 종료 or 다음 턴
```

### 13.2 리졸브 순서

```
아군 Front → 아군 Middle → 아군 Back
→ 적 Front → 적 Middle → 적 Back
```

### 13.3 최대 턴 수

30턴 초과 시 **패배** (`03` §2).

## 14. BattleContext

```csharp
public class BattleContext

}
```

## 16. Targeting 시스템

### 16.1 TargetType

```csharp
public enum TargetType
{
    Self,
    SingleEnemy,
    AllEnemies,
    RandomEnemy,
    SingleAlly,
    AllAllies,
    Everyone,
    Corpse,           // 시체 대상 (무덤지기 등)
    SacrificeTarget   // 희생 대상 지정
}
```

### 16.2 타겟 검증 규칙

타겟 검증은 반드시 **Resolve 시점**에 수행.

```
카드 사용 → Target 선택 → Action 생성 → Queue 삽입
                                              ↓
                                       [Queue 처리 시점]
                                              ↓
                                       Target 재검증
                                       (IsDead? IsTargetable?)
                                              ↓
                                       무효 시 Action Skip
```

Queue 삽입 시점에 타겟 고정 금지. 삽입 후 타겟이 사망할 수 있음.

### 16.3 AI 타겟팅 우선순위

| 우선순위 | 조건 |
|---|---|
| 1 | 처형 가능 대상 (HP % 기준) |
| 2 | 플레이어 치명타 가능 |

## 17. Runtime Snapshot (디버그 / 리플레이)

### 17.1 목적

디버깅 및 리플레이 지원. 전투 재현 가능성 보장.

### 17.2 저장 데이터

```csharp
public class BattleSnapshot
{
    public int TurnCount;
    public int RandomSeed;

    // 유닛 상태
    public List<UnitSnapshot> Allies;
    public List<UnitSnapshot> Enemies;

    // 덱 상태
    public List<string> DrawPile;       // CardData.Id 목록
    public List<string> Hand;
    public List<string> DiscardPile;

    // Queue 상태 (디버그용)
    public List<string> MainQueueLog;
    public List<string> TriggerQueueLog;
}

public class UnitSnapshot
{
    public string UnitId;
    public int CurrentHP;
    public int Shield;
    public List<StatusSnapshot> Statuses;
}
```

## 20. 절대 금지 목록

```
❌ target.CurrentHP -= n;          → DamageAction 사용
❌ target.Remove();               → DeathAction + Death Queue 사용
❌ Animation Event → 로직 수정     → Presentation Layer 분리
❌ UnityEngine.Random 직접 사용   → BattleRandom 사용
❌ Queue 우회 실행                 → Enqueue 강제
❌ ScriptableObject 전투 중 수정  → Runtime 객체만 수정
❌ Queue 처리 중 AI 재계산         → 무한 루프 위험
❌ Trigger 내부 직접 Action 실행  → TriggerQueue 삽입
```
