# 다크 레기온 — 아트 방향과 에셋 목록

> **정본 결정**: `01` §7 **D-43** (화풍·해상도·움직임·색·UI), D-39 (PC 1920×1080, URP 2D, uGUI)
> **이슈**: #32 · 연출 목록은 `28`, 사운드는 #31
> **아직 정하지 않은 것**: 그림 제작 방식 (직접·외주·구매 등). 사용자가 선택하지 않아서 2단계 전에 다시 묻는다 (§6)
> **결정과 초안의 구분**: §1 표는 사용자 결정(D-43)이다. §1.1·§2·§3·§4에서 **[초안]** 표시가 붙은 값(외곽선, 엘리트·토큰·카드 그림 크기, 붉은색 사용 규칙, 트윈 수치)은 결정을 구현하려고 Claude가 채운 초안이다. 사용자가 바꾸라고 하면 새 D 번호 없이 이 문서에서 고친다

## 1. 방향 (D-43)

| 항목 | 결정 |
|---|---|
| 화풍 | **픽셀 아트**. 콘셉트는 그대로 "Stylized Dark Fantasy, 붉은 조명, 심연 분위기" (`29` §1) |
| 기준 해상도 | **640×360**을 정수 **3배**로 키워 1920×1080에 출력. URP 2D **Pixel Perfect Camera** (Reference Resolution 640×360) |
| 움직임 | **정지 그림 1장 + 코드 트윈**. 프레임 애니메이션·본 애니메이션은 쓰지 않는다 |
| 층별 색 | **공통 어둠 바탕 + 층별 강조색** (§3) |
| UI | **고해상도**. 카드 틀·버튼·글자(TextMeshPro 한글)·아이콘은 1920×1080 원래 해상도. 픽셀은 월드(필드·배경)와 카드 안 그림에만 쓴다 |

### 1.1 픽셀 규칙

텍스처 가져오기·배치·카드 안 그림 배율은 D-43(픽셀 아트, 640×360 ×3)을 Unity에서 구현할 때의 **기술 기본값**이다. PPU 32는 Unity 단위 계산용이며 그림 크기와 관계없다. **[초안]** 표시 행은 아트 규칙 초안이다.

| 규칙 | 값 |
|---|---|
| 텍스처 가져오기 | Filter Mode **Point**, Compression **None**, Pixels Per Unit **32** |
| 배치 | 월드 스프라이트 위치는 1px 단위로 스냅 (Pixel Perfect Camera) |
| 회전·비정수 확대 **[초안]** | 월드 스프라이트에 쓰지 않는다. 트윈의 크기 변화는 정수배 대신 **짧은 시간(≤0.15초)** 에만 허용 (§4) |
| 외곽선 **[초안]** | 어두운 바탕에서 구분되도록 1px 외곽선. 아군은 차가운 톤, 적은 따뜻한 톤 외곽선 |
| 카드 안 그림 | 픽셀 그림을 고해상도 카드 틀 안에 **정수배(×3)** 로 넣는다 |

## 2. 크기 기준 (기준 해상도 640×360 기준 픽셀)

일반 몬스터 64×64와 보스 128×128은 D-43 선택지 ⑤에 적힌 크기다. 나머지(토큰·엘리트·카드 그림)는 **[초안]** 이다.

| 대상 | 캔버스 | 화면에서 (×3) | 비고 |
|---|---|---|---|
| 아군 몬스터 (Lv1~Lv3) | 64×64 | 192×192 | 레벨이 높을수록 캔버스를 더 채운다. 캔버스 크기는 같다 |
| 해골 토큰 (`NEC_ACT_002`) **[초안]** | 48×48 | 144×144 | 토큰을 몬스터보다 작게 그리는 것도 초안 |
| 일반 적 | 64×64 | 192×192 | |
| 엘리트 | 96×96 | 288×288 | |
| 보스 | 128×128 | 384×384 | 배치는 `37` §2 적 슬롯 규칙을 따른다 |
| Skill·Action 카드 그림 | 64×48 | 192×144 | 카드 틀 안 그림 영역 |
| 몬스터 카드 그림 **[초안]** | — | — | 필드 스프라이트를 카드 안에 그대로 쓰고 따로 그리지 않는다. 사용자가 정한 것이 아니라 그림 수를 줄이려는 제작 초안이다. 제작 방식(§6)을 정할 때 함께 묻는다 |
| 층 배경 | 640×360 | 1920×1080 | 필드 뒤 한 장 |

필드 배치: 아군 3슬롯 + 적 5슬롯(Ex 포함)이 640px 폭에 64px 캔버스로 들어간다. 손패·버튼은 고해상도 UI라서 기준 해상도 계산에 들어가지 않는다 (`37` §2).

## 3. 색

- **바탕**: 모든 층 공통 어두운 톤. 몬스터·적 그림은 이 바탕 위에서 만들고 층마다 다시 칠하지 않는다.
- **층 강조색**: 배경 조명, 필드 바닥, 보스 연출에만 쓴다.

아래 다섯 색은 **[초안]** 이다. 선택지 ④의 설명에 "예:"로 적었던 색이고, 사용자는 원칙(공통 어둠 + 층별 강조색)만 골랐다.

| 층 | 테마 | 강조색 **[초안]** |
|---|---|---|
| 1 | 굶주림 | 탁한 녹색 |
| 2 | 화염 | 주황 |
| 3 | 피와 육체 | 진홍 |
| 4 | 심판 | 금색 |
| 5 | 심연 | 보라 |

- **[초안]** **붉은색**은 층과 관계없이 **희생·Crystal·피해** 표시에만 쓴다. 그래서 1·2·4·5층에서는 붉은색이 "대가"를 뜻하는 신호로 읽힌다. 3층(진홍)에서는 배경 채도를 낮춰 구분한다.

## 4. 움직임 (정지 그림 + 코드 트윈)

`28` 연출 목록을 그림 1장으로 구현한다. 아래 수치는 **[초안]** 이다 (`28`에 정해진 shake 0.12초는 제외). 트윈은 Presentation 계층에서만 실행하고 로직을 바꾸지 않는다 (`05` §1 Rule 5).

| 상황 | 트윈 |
|---|---|
| 대기 | 2초 주기 1px 위아래 흔들림 (몬스터마다 시작 시점 다르게) |
| 공격 | 대상 쪽으로 8px 밀고 복귀 (0.12초) |
| 피격 | 흰색 번쩍임 1프레임 + 2px 좌우 흔들림 (`28` shake 0.12초) |
| 소환 | 아래에서 위로 4px 올라오며 나타남 |
| 희생·사망 | 붉은색 번쩍임 후 아래로 사라짐 |
| 보스 페이즈 전환 | 화면 흔들림 + 층 강조색 플래시 (`28` BossPhaseChanged) |

## 6. 제작 방식 (결정 전)

그림을 누가 만드는지는 사용자가 정하지 않았다 (#32 근거 댓글 ③). 2단계 착수 전에 다시 선택지 질문으로 받는다. 이때 몬스터 카드 그림을 필드 스프라이트와 따로 그릴지(§2 [초안])와 층 강조색 다섯 개(§3 [초안])도 함께 묻는다.

1단계 구현은 그림 없이 진행할 수 있도록 **임시 스프라이트**를 쓴다. 이것은 구현 편의를 위한 것이고 아트 결정이 아니다.
- §2와 같은 캔버스 크기의 단색 도형 + 이름 첫 글자. 아군은 차가운 색, 적은 따뜻한 색
- 파일 이름은 데이터 ID 그대로(`NEC_MON_001.png`, `ENE_1F_GHO_001.png`). 나중에 같은 이름으로 바꿔 넣으면 코드 수정 없이 교체된다
