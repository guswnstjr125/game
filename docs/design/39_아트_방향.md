# 다크 레기온 — 아트 방향과 에셋 목록

> **정본 결정**: `01` §7 **D-43** (화풍·해상도·움직임·색·UI), D-39 (PC 1920×1080, URP 2D, uGUI)
> **이슈**: #32 · 연출 목록은 `28`, 사운드는 #31
> **제작 방식**: **AI 생성** (사용자 지시 「이미지는 ai를 사용 할거야」, D-43). 작업 흐름은 §6 [초안], 어떤 AI 도구를 쓸지는 §6.4 시험 뒤 정한다 (D-44 후보)
> **결정과 초안의 구분**: §1 표는 사용자 결정(D-43)이다. §1.1·§2·§3·§4에서 **[초안]** 표시가 붙은 값(외곽선, 엘리트·토큰·카드 그림 크기, 붉은색 사용 규칙, 트윈 수치)은 결정을 구현하려고 Claude가 채운 초안이다. 사용자가 바꾸라고 하면 새 D 번호 없이 이 문서에서 고친다

## 1. 방향 (D-43)

| 항목 | 결정 |
|---|---|
| 화풍 | **픽셀 아트**. 콘셉트는 그대로 "Stylized Dark Fantasy, 붉은 조명, 심연 분위기" (`29` §1) |
| 기준 해상도 | **640×360**을 정수 **3배**로 키워 1920×1080에 출력. URP 2D **Pixel Perfect Camera** (Reference Resolution 640×360) |
| 움직임 | **정지 그림 1장 + 코드 트윈**. 프레임 애니메이션·본 애니메이션은 쓰지 않는다 |
| 층별 색 | **공통 어둠 바탕 + 층별 강조색** (§3) |
| UI | **고해상도**. 카드 틀·버튼·글자(TextMeshPro 한글)·아이콘은 1920×1080 원래 해상도. 픽셀은 월드(필드·배경)와 카드 안 그림에만 쓴다 |

### 1.1 픽셀 규칙

텍스처 가져오기·배치·카드 안 그림 배율은 D-43(픽셀 아트, 640×360 ×3)을 Unity에서 구현할 때의 **기술 기본값**이다. PPU 32는 Unity 단위 계산용이며 그림 크기와 관계없다. **[초안]** 표시 행은 아트 규칙 초안이다.

| 규칙 | 값 |
|---|---|
| 텍스처 가져오기 | Filter Mode **Point**, Compression **None**, Pixels Per Unit **32** |
| 배치 | 월드 스프라이트 위치는 1px 단위로 스냅 (Pixel Perfect Camera) |
| 회전·비정수 확대 **[초안]** | 월드 스프라이트에 쓰지 않는다. 트윈의 크기 변화는 정수배 대신 **짧은 시간(≤0.15초)** 에만 허용 (§4) |
| 외곽선 **[초안]** | 어두운 바탕에서 구분되도록 1px 외곽선. 아군은 차가운 톤, 적은 따뜻한 톤 외곽선 |
| 카드 안 그림 | 픽셀 그림을 고해상도 카드 틀 안에 **정수배(×3)** 로 넣는다 |

## 2. 크기 기준 (기준 해상도 640×360 기준 픽셀)

일반 몬스터 64×64와 보스 128×128은 D-43 선택지 ⑤에 적힌 크기다. 나머지(토큰·엘리트·카드 그림)는 **[초안]** 이다.

| 대상 | 캔버스 | 화면에서 (×3) | 비고 |
|---|---|---|---|
| 아군 몬스터 (Lv1~Lv3) | 64×64 | 192×192 | 레벨이 높을수록 캔버스를 더 채운다. 캔버스 크기는 같다 |
| 해골 토큰 (`NEC_ACT_002`) **[초안]** | 48×48 | 144×144 | 토큰을 몬스터보다 작게 그리는 것도 초안 |
| 일반 적 | 64×64 | 192×192 | |
| 엘리트 **[초안]** | 96×96 | 288×288 | |
| 보스 | 128×128 | 384×384 | 배치는 `37` §2 적 슬롯 규칙을 따른다 |
| Skill·Action 카드 그림 **[초안]** | 64×48 | 192×144 | 카드 틀 안 그림 영역 |
| 몬스터 카드 그림 **[초안]** | — | — | 필드 스프라이트를 카드 안에 그대로 쓰고 따로 그리지 않는다. 사용자가 정한 것이 아니라 그림 수를 줄이려는 제작 초안이다. AI 도구를 정할 때(§6.4) 함께 묻는다 |
| 층 배경 | 640×360 | 1920×1080 | 필드 뒤 한 장 |
| 이벤트 그림 **[초안]** | 320×180 | 960×540 | 이벤트 화면 상단 (`37` §2.5, `01` D-50). 크기는 초안 |

필드 배치: 아군 3슬롯 + 적 5슬롯(Ex 포함)이 640px 폭에 64px 캔버스로 들어간다. 손패·버튼은 고해상도 UI라서 기준 해상도 계산에 들어가지 않는다 (`37` §2).

## 3. 색

- **바탕**: 모든 층 공통 어두운 톤. 몬스터·적 그림은 이 바탕 위에서 만들고 층마다 다시 칠하지 않는다.
- **층 강조색**: 배경 조명, 필드 바닥, 보스 연출에만 쓴다.

아래 다섯 색은 **[초안]** 이다. 선택지 ④의 설명에 "예:"로 적었던 색이고, 사용자는 원칙(공통 어둠 + 층별 강조색)만 골랐다.

| 층 | 테마 | 강조색 **[초안]** |
|---|---|---|
| 1 | 굶주림 | 탁한 녹색 |
| 2 | 화염 | 주황 |
| 3 | 피와 육체 | 진홍 |
| 4 | 심판 | 금색 |
| 5 | 심연 | 보라 |

- **[초안]** **붉은색**은 층과 관계없이 **희생·Crystal·피해** 표시에만 쓴다. 그래서 1·2·4·5층에서는 붉은색이 "대가"를 뜻하는 신호로 읽힌다. 3층(진홍)에서는 배경 채도를 낮춰 구분한다.

## 4. 움직임 (정지 그림 + 코드 트윈)

`28` 연출 목록을 그림 1장으로 구현한다. 아래 수치는 **[초안]** 이다 (`28`에 정해진 shake 0.12초는 제외). 트윈은 Presentation 계층에서만 실행하고 로직을 바꾸지 않는다 (`05` §1 Rule 5).

| 상황 | 트윈 |
|---|---|
| 대기 | 2초 주기 1px 위아래 흔들림 (몬스터마다 시작 시점 다르게) |
| 공격 | 대상 쪽으로 8px 밀고 복귀 (0.12초) |
| 피격 | 흰색 번쩍임 1프레임 + 2px 좌우 흔들림 (`28` shake 0.12초) |
| 소환 | 아래에서 위로 4px 올라오며 나타남 |
| 희생·사망 | 붉은색 번쩍임 후 아래로 사라짐 |
| 보스 페이즈 전환 | 화면 흔들림 + 층 강조색 플래시 (`28` BossPhaseChanged) |

## 6. 제작 방식 — AI 생성

**결정 (D-43)**: 그림은 **AI로 생성**한다. 근거는 사용자 지시 「이미지는 ai를 사용 할거야」다. 처음 질문 ③에서는 선택이 없었고, 그 뒤에 이 지시가 나왔다. 사용자는 그림을 직접 그리지 않는다(「내가 그림을 못그리는데 가능해?」). 그래서 아래 흐름은 그림 실력 없이 할 수 있는 작업만으로 짰다.

§6.1~§6.5는 모두 **[초안]** 이다. 도구 이름·가격은 2026-11 조사 기준이며, 출처 대부분이 업체 블로그와 2차 기사라 쓰기 전에 각 사이트에서 다시 확인한다.

### 6.1 도구 종류 [초안]

| 방식 | 도구 예 | 장점 | 단점 |
|---|---|---|---|
| **픽셀 전용 생성 (우선 시험)** | Retro Diffusion, PixelLab | 픽셀이 실제 격자에 맞춰 나온다. 일반 AI의 "픽셀처럼 보이는 그림" 문제가 적다 | 도구마다 그림체가 달라 시험이 필요하다 |
| 기준 그림체 학습 | Scenario 등의 스타일 학습(LoRA) | 기준 그림 10~30장으로 학습하면 158점의 그림체를 맞추기 쉽다 | 기준 세트가 먼저 있어야 한다 |
| 일반 이미지 AI + 축소 | 범용 이미지 생성 모델 | 그림이 다양하다 | 64×64로 줄이고 팔레트를 정리하는 후처리가 매번 필요하고 격자가 어긋나기 쉽다 |

움직임은 코드 트윈이라(§4) 도구의 애니메이션·방향 회전 기능은 고르는 기준에 넣지 않는다.

### 6.2 작업 흐름 [초안]

1. **기준 세트**: 1층 NEC 몬스터 5~8장을 여러 장씩 생성해서 가장 나은 것을 고르고, §6.3대로 다듬는다. 64×64 캔버스, 1px 외곽선, 공통 어둠 팔레트의 기준이 된다.
2. **그림체 고정**: 이후 생성마다 기준 세트를 스타일 참고 이미지로 넣는다. 장수가 많아지면 기준 세트로 스타일 학습을 쓴다.
3. **팔레트 고정**: 모든 그림을 같은 팔레트로 줄인다. 층 색은 조명·배경 강조색으로만 바꾸므로(§3) 몬스터 그림은 한 팔레트로 통일한다.
4. **다듬기**: §6.3의 다섯 가지 작업.
5. **저장**: 파일 이름을 데이터 ID로(`NEC_MON_001.png`) 저장하고, 같은 이름의 임시 스프라이트(§6.5)를 덮어쓴다.
6. **기록**: 그림마다 사용한 도구, 설명문(프롬프트), 고른 이유, 고친 부분을 남긴다 (§6.6 저작권 대비). 위치는 `DarkLegion/Assets/_Project/Art/_log/`(빌드에 넣지 않음).

### 6.3 그림을 그리지 않고 하는 다듬기 [초안]

| 작업 | 방법 |
|---|---|
| 팔레트 맞추기 | 픽셀 편집기의 "팔레트로 색 줄이기"를 한 번 실행 |
| 튀는 점 지우기 | 외곽 밖에 떨어진 1~2픽셀 삭제 |
| 외곽선 정리 | 끊긴 1px 외곽선을 연필로 이어 줌 |
| 크기·위치 맞추기 | 64×64 캔버스 안에서 발 높이를 맞춤 |
| 실루엣 확인 | 그림을 검게 채워 다른 몬스터와 구분되는지 본다. 구분되지 않으면 다시 생성 |

도구는 픽셀 편집기 하나(예: Aseprite)면 된다. 기준 세트(5~8장)를 만드는 것이 가장 어려우면, **기준 세트만** 픽셀 아티스트에게 다듬어 달라고 맡기고 나머지는 그 세트를 참고 이미지로 생성하는 방법이 있다.

### 6.4 도구 시험 [초안]

- 1단계 몬스터 20장 중 1층 NEC 5장을 골라, 픽셀 전용 도구 두 개로 같은 조건(64×64, 같은 설명문)에서 생성한다.
- 비교 기준: ① 격자 정확도 ② 5장 그림체 일치 ③ 한 장 다듬는 시간
- 결과를 보고 사용자가 도구를 고른다 (D-44 후보, 선택지 질문 + 사용자 승인 댓글). 이때 몬스터 카드 그림 재사용(§2)과 층 강조색 다섯 개(§3)도 함께 묻는다.

### 6.5 1단계 임시 스프라이트

1단계 구현은 그림 없이 진행할 수 있도록 **임시 스프라이트**를 쓴다. 이것은 구현 편의를 위한 것이고 아트 결정이 아니다. 그림 작업이 1단계 일정을 막지 않는다.
- §2와 같은 캔버스 크기의 단색 도형 + 이름 첫 글자. 아군은 차가운 색, 적은 따뜻한 색
- 파일 이름은 데이터 ID 그대로(`NEC_MON_001.png`, `ENE_1F_GHO_001.png`). 나중에 같은 이름으로 바꿔 넣으면 코드 수정 없이 교체된다
- 위치: `DarkLegion/Assets/_Project/Art/Placeholder/`
