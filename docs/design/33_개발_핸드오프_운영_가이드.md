## 1. 첫날(착수일) 실행 순서

1) `03_MVP_전층_스펙.md`로 범위 고정  
2) `01_MVP_설계_동결_선언.md` 확인 — 특히 §7 결정 로그(D-01~). 다른 문서와 충돌하면 §7이 정본  
3) `31_MVP_이슈_초안.md` §0의 단계별 목록대로 이슈 트래커에 등록 (1단계 이슈부터)  
4) `32_MVP_검증_시나리오_매트릭스.md`를 테스트 계획으로 복사 (단계 1 시나리오부터)  
5) `02_개발_로드맵.md` §4 기준 주차/우선순위 확정  
6) 저장소 루트에서 `python3 tools/check_design.py` 실행 → 모든 규칙 그룹 OK 확인

## 2. 역할별 체크리스트

### 개발자

- [ ] 작업 시작 전 참조 문서 3개 이상 지정
- [ ] 이슈 DoD/테스트 항목 선입력
- [ ] MVP 범위 외 항목(Post-MVP) 제외 표시

### 리뷰어

- [ ] 설계 우선순위 위반 여부 검토 (`03_MVP_전층_스펙.md` 우선, 결정은 `01` §7)
- [ ] 문서-구현-테스트 연결성 확인
- [ ] 폴백/예외 처리 누락 여부 확인
- [ ] 설계 변경 PR: `check_design.py` 출력의 `commit=`이 PR head와 같고 모든 그룹 OK인지 확인
- [ ] 작성자가 아닌 사람·에이전트가 리뷰한 뒤 병합

### PM/기획

- [ ] 이슈 순서가 `02_개발_로드맵.md` §4·`31` §0과 동일한지 확인
- [ ] 범위 확장 요청 시 동결 규칙 준수
- [ ] 위험 항목(밸런스/OTK/루프) 모니터링
