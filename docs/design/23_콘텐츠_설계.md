## 1. 유물 시스템 (Relic System)

### 설계 목표

유물은 플레이 스타일을 변화시키는 메타 강화 요소다.

- 카드보다 강력하지만 수량 제한
- 런 방향성을 결정
- 특정 클래스 시너지 제공
- 희생 / 융합 / 상태이상 빌드 강화
- 런마다 조합 다양성 제공

### 유물 희귀도

| 등급 | 설명 |
|---|---|
| Common | 범용 강화 |
| Uncommon | 특정 빌드 강화 |
| Rare | 강한 방향성 제공 |
| Legendary | 런 핵심 변경 |
| Boss | 보스 처치 전용 |

### RelicData 구조

```csharp
public enum RelicRarity
{
    Common, Uncommon, Rare, Legendary, Boss
}

public class RelicData : ScriptableObject
{
    public string RelicId;
    public string RelicName;
    public RelicRarity Rarity;
    public Sprite Icon;
    public string Description;

    public List<TriggerDefinition> Triggers;
    public List<EffectDefinition> PassiveEffects;
}
```

### RuntimeRelic

```csharp
public class RuntimeRelic
{
    public RelicData Data;
    public bool Disabled;
}
```

### 유물 트리거 예시

| 유물 | 효과 |
|---|---|
| 피의 잔 | 턴당 **첫 희생에만** Crystal +1 (`01` D-04) |
| 저주받은 두개골 | 아군 사망 시 Draw +1 |
| 타락한 성배 | 턴 시작 Burn 2 부여, Crystal +1 |
| 심연의 심장 | HP 50% 이하 시 공격력 +50% |
| 금단의 촛불 | 첫 상태이상 면역 |

### 유물 획득 규칙

| 상황 | 보상 |
|---|---|
| 엘리트 승리 | 유물 선택 1개 |
| 보스 승리 | Boss Relic 1개 |
| 이벤트 | 확률 획득 |
| 보물방 | 랜덤 유물 |

## 2. 이벤트 시스템

### EventData 구조

```csharp
public class EventData : ScriptableObject
{
    public string EventId;
    public string Title;
    public string Description;
    public List<EventOption> Options;
}

public class EventOption
{
    public string Text;
    public List<ConditionDefinition> Conditions;
    public List<EffectDefinition> Results;
}
```

### 이벤트 카테고리

| 타입 | 설명 |
|---|---|
| RiskReward | HP ↔ 보상 |
| Curse | 저주 ↔ 강한 보상 |
| Sacrifice | 몬스터 희생 요구 |
| Greed | 골드 관련 |
| Lore | 세계관 |
| EliteTrigger | 전투 강제 |

### MVP 이벤트 상세

#### 악마 계약

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | 최대 HP -10 → Rare 카드 획득 |
| 2 | — | 저주 카드 추가 → 유물 획득 |
| 3 | — | 거절 |

#### 피의 제단

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | HP 20 소모 → 카드 강화 |
| 2 | 몬스터 1마리 | 몬스터 희생 → 랜덤 강화 |
| 3 | — | 떠난다 |

#### 저주 상자

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | 연다 → 유물 획득 + 저주 확률 |
| 2 | — | 파괴한다 → 골드 획득 |
| 3 | — | 무시 |

#### 영혼 감옥

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | 영혼 해방 → 보상 또는 적 등장 |
| 2 | — | 영혼 흡수 → HP 회복 |
| 3 | — | 떠난다 |

#### 방랑 상인 (`EVT_WANDER_MERCHANT`)

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | 골드 8 이상 | 골드 8 → 일반 카드 3택1 |
| 2 | HP 8 초과 | HP 8 소모 → 카드 1장 |
| 3 | — | 떠난다 |

#### 잊힌 제단 (`EVT_FORGOTTEN_SHRINE`)

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | HP 15 회복 |
| 2 | 몬스터 1마리 | 희생 → 카드 강화 1장 |
| 3 | — | 떠난다 |

#### 어둠의 내기 (`EVT_DARK_WAGER`)

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | 50% 골드 25 / 50% HP -12 |
| 2 | — | 50% 언커먼 카드 / 50% 저주 1장 |
| 3 | — | 떠난다 |

#### 묘지의 속삭임 (`EVT_GRAVE_WHISPER`)

| 선택지 | 조건 | 결과 |
|---|---|---|
| 1 | — | 저주 1장 → Rare 카드 3택1 |
| 2 | — | HP 8 회복 |
| 3 | — | 떠난다 |

> MVP는 위 8종이다. 각 층에서 실제로 뽑히는 집합은 공통 4종과 그 층에 배정된 신규 2종이다 (`Event_FloorPool`, `01` D-10).

## 3. 키워드 시스템

### 설계 목표

텍스트 중복 감소 및 카드 확장성 확보.

### KeywordData

```csharp
public class KeywordData : ScriptableObject
{
    public string KeywordId;
    public string DisplayName;
    public string Description;
}
```

### 핵심 키워드 목록

| 키워드 | 설명 |
|---|---|
| Exhaust | 사용 후 ExhaustPile 이동 |
| Ethereal | 턴 종료 시 미사용이면 소멸 |
| Deathrattle | 사망 시 효과 발동 |
| Echo | 다음 턴 재사용 |
| Consume | 영구 강화 후 제거 |
| Ignite | Burn 즉시 폭발 |
| Soulbound | 희생 불가 |
| Frenzy | 피해 시 공격력 증가 |
| Decay | 턴마다 HP 감소 |
| Spawn | 즉시 소환 |

### 카드 키워드 사용 예시

```
죽음의 사도
[Deathrattle] 아군 전체 Burn 2 부여
```

## 4. 융합 레시피 시스템

### FusionRecipeData

```csharp
public class FusionRecipeData : ScriptableObject
{
    public string RecipeId;
    public MonsterData MaterialA;
    public MonsterData MaterialB;
    public MonsterData Result;
    public bool Symmetric;
}
```

### 융합 타입

| 타입 | 설명 |
|---|---|
| Fixed Recipe | 고정 결과 |
| Random Pool | 클래스 기반 랜덤 |
| Mutation | 낮은 확률 변이 |
| Abyss Fusion | 저주형 초강력 |

### MVP 융합 레시피

| 재료 A | 재료 B | 결과 |
|---|---|---|
| 구울 | 구울 | 식인 구울 |
| 뼈 병사 | 영혼 토템 | 저주 기사 |
| 구울 | 영혼 토템 | 시체 포식자 |
| Flesh계 | Demon계 | 살덩이 악마 |

### 랜덤 융합 확률 규칙

```
같은 클래스:
  70% 해당 클래스 결과
  20% 중립 결과
  10% 변이

무속성 + 클래스:
  50% 클래스 상위 레벨
  50% 무속성 상위 레벨
```

> MVP 적용: 변이(Mutation)·Abyss Fusion 비활성 → 같은 클래스 80% / 중립 20%. 정본 `01_MVP_설계_동결_선언.md` §7 **D-03**

## 6. 맵 생성 시스템 (풀 버전 / Post-MVP)

> MVP 전층 런은 [03_MVP_전층_스펙.md](03_MVP_전층_스펙.md) §0·§2의 **층당 9노드 단일 경로**를 정본으로 사용한다.  
> 노드 2지선다와 이 절의 분기 맵은 Post-MVP다 (`01` D-11). MVP 경로는 단일 경로만 쓴다.

### 설계 목표

Slay the Spire 스타일 경로 선택.

- 리스크 선택 가능
- 엘리트 회피 가능
- 보상 루트 존재
- 지나친 RNG 방지

### 노드 타입

| 노드 | 설명 |
|---|---|
| Battle | 일반 전투 |
| Elite | 엘리트 |
| Boss | 보스 |
| Event | 이벤트 |
| Shop | 상점 (MVP: 2층+ 노드6 Event 30% 치환 옵션) |
| Rest | 휴식 |
| Treasure | 보물 (Post-MVP) |
| Mimic | 함정 (Post-MVP) |

### 맵 생성 규칙

| 규칙 | 설명 |
|---|---|
| 시작 노드 1개 | 시작점 고정 |
| 최소 루트 3개 | 선택 보장 |
| 엘리트 연속 금지 | 난이도 급등 방지 |
| 보스 직전 휴식 보장 | 안정성 확보 |
| 상점 최소 1개 | 런 안정화 |

### MVP 고정 프로파일 (`03_MVP_전층_스펙.md` 정본)

| 항목 | 규칙 |
|---|---|
| 경로 | 층당 단일 경로. 분기·2지선다는 Post-MVP |
| 노드 수 | 층당 9 (Battle 4 / Event 2 / Elite 1 / Rest 1 / Boss 1) |
| Shop | 선택 규칙(2층+ 노드6 Event 30% 치환)만 적용 가능, 기본 템플릿에는 미포함 |
| Treasure/Mimic | Post-MVP (MVP에는 등장하지 않음) |

### MapNode 구조

```csharp
public class MapNode
{
    public int Depth;
    public StageType Type;
    public List<MapNode> Connections;
}
```
