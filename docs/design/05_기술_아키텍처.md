## 1. 절대 규칙 (Global Rules)

아래 규칙은 어떤 상황에서도 깨지면 안 된다.

---

### Rule 1 — 즉시 실행 금지

모든 전투 효과는 반드시 Queue를 통해 실행된다.

```csharp
// 금지
target.TakeDamage(10);

// 허용
queue.Enqueue(new DamageAction(...));
```

---

### Rule 2 — Runtime Only Mutation

전투 중 상태 변경은 Runtime 객체만 허용.

```
허용: RuntimePlayer / RuntimeEnemy / RuntimeStatus / RuntimeResource
금지: ScriptableObject 직접 수정
```

---

### Rule 3 — Death 즉시 제거 금지

HP <= 0 시 즉시 제거 금지.  
`IsDead = true` 및 `IsTargetable = false` 설정 후 **Death Queue**에서 처리한다. 슬롯은 Battlefield 제거 전까지 유지한다.

```
HP <= 0 감지
→ IsDead = true, IsTargetable = false
→ DeathAction을 Death Queue에 등록
→ (현재 Main/Trigger Flush 구간 내) Death Queue Flush
→ DeathAction 실행
→ OnDeath Trigger (Deathrattle 포함)
→ Drop 처리
→ 슬롯 제거 및 Runtime 정리
```

---

### Rule 4 — 카드 직접 실행 금지

카드는 효과를 실행하지 않는다.  
카드는 `BattleAction` 생성만 수행한다.

---

### Rule 5 — Animation Is Presentation Only

애니메이션은 로직을 변경하지 않는다.

```
금지: Animation → Runtime 직접 수정
허용: Logic Queue → Presentation Event → Animation Queue → VFX
```

애니메이션 실패 시에도 전투 로직은 정상 진행 보장.

---

## 2. 플랫폼 계층 구조

```
Content Layer        ← 디자이너 작업 (ScriptableObject)
↓
Definition Layer     ← 실행 정의 (EffectDefinition, TargetRule 등)
↓
Runtime Layer        ← 전투 중 실제 상태 저장
↓
Execution Layer      ← 전투 실행 (Queue, Resolver, TurnManager 등)
↓
Presentation Layer   ← 연출 전용 (UI, Animation, VFX, Sound)
```

| 계층 | 포함 요소 | 특징 |
|---|---|---|
| Content | CardData, EnemyData, StatusData, RelicData | 정적 데이터만 / Runtime 상태 저장 금지 |
| Definition | EffectDefinition, TargetRule, TriggerDefinition | "무엇을 실행할 것인가" 정의 |
| Runtime | RuntimePlayer, RuntimeEnemy, RuntimeCard, RuntimeStatus | 전투 중 변경 가능 / Save 대상 |
| Execution | QueueProcessor, BattleAction, TriggerBus, TurnManager | 실제 전투 실행 |
| Presentation | UI, Animation, VFX, Sound | 로직 변경 금지 |

## 4. Queue 아키텍처

### Queue 종류 및 Flush 우선순위

등록 큐는 세 종류이며, **Flush 순서**는 아래와 같다 (04_시스템_설계.md · 06_전투_코어_상세설계.md 정본).

```
Main Queue      ← 일반 행동 (Damage, Heal, Draw, Summon, Sacrifice 등)
Trigger Queue   ← OnDamageTaken, OnDeath, OnDraw 등
Death Queue     ← DeathAction 전용
```

**한 Main Action 실행 직후:**

```
1. Death Queue Flush   ← 사망·슬롯 정리 (타겟 검증 안정화)
2. Trigger Queue Flush ← Trigger 실행 중에도 Death 재-Flush
```

Main Queue가 비면 최종 Death Queue를 한 번 더 정리한다.

### BattleAction 기본 구조

```csharp
public abstract class BattleAction
{
    public RuntimeUnit Source;
    public RuntimeUnit Target;
    public BattleActionType Type;
    public abstract void Execute(BattleContext context);
}
```

### Action 종류

- DamageAction / HealAction
- ApplyStatusAction / RemoveStatusAction
- DrawCardAction / DiscardCardAction / ExhaustCardAction / MoveCardAction
- GainCrystalAction (희생·카드 보상)
- SummonAction / SacrificeAction
- DeathAction / DestroyAction (환경 오브젝트)
- SpawnRewardAction

### QueueProcessor

```csharp
public class QueueProcessor
{
    private Queue<BattleAction> mainQueue;
    private Queue<BattleAction> triggerQueue;
    private Queue<BattleAction> deathQueue;

    public void Process()
    {
        while (mainQueue.Count > 0)
        {
            BattleAction action = mainQueue.Dequeue();
            action.Execute(context);

            FlushDeathQueue();
            FlushTriggerQueue();    // Trigger 1건 실행마다 FlushDeathQueue 재호출
        }
        FlushDeathQueue();
    }
}
```

### Nested Queue 규칙

Nested Queue는 허용된다. 새 Action은 **즉시 실행하지 않고** 해당 Queue에 Enqueue한다.

```
Attack Action 실행
→ OnDamageDealt → Trigger Queue
→ HP <= 0 → Death Queue
→ Death Queue Flush
→ Trigger Queue Flush
```

단, **현재 Action의 Execute() 본문이 끝나기 전에 Queue에서 다음 Action을 Dequeue하지 않는다**.

### 무한 루프 방지

| 항목 | 제한 | 비고 |
|---|---|---|
| 최대 턴 수 | 30턴 | 초과 시 강제 종료 |
| 최대 Queue 크기 | 500 | Main+Trigger+Death 합산 |
| Trigger Flush 1회당 반복 | 20회 | `MaxTriggerIterationsPerFlush` |
| MaxTriggerDepth | 32 | 중첩 Trigger 깊이 |

## 5. Trigger / Event Bus

### 이벤트 종류

- OnBattleStart
- OnTurnStart / OnTurnEnd
- OnCardPlayed
- OnDamageTaken / OnDamageDealt (피해 파이프라인 Before/After와 별도; 상세는 06_전투_코어_상세설계.md §11)
- OnHeal
- OnDeath
- OnSacrifice / OnSummon
- OnStatusApplied
- OnDraw

### Trigger Priority

```csharp
public enum TriggerPriority { Before = 0, On = 1, After = 2 }
```

같은 Priority 내에서는 등록 순서대로 처리한다.

### Trigger 흐름

```
이벤트 발생
→ TriggerBus에서 구독자 검색 (Priority 순)
→ BattleAction 생성
→ Trigger Queue 삽입
→ Flush 시 Death Queue 선행 처리
```

**핵심 규칙**: Event는 상태를 직접 수정하지 않는다. 오직 BattleAction 생성만 수행.

## 15. Runtime 코드 클래스 상세

### RuntimeStat

HP / ATK / DEF 각각 독립 인스턴스. Weak·Vulnerable·치명타는 `MultiplicativeModifier`로 적용 (04_시스템_설계.md §8).

```csharp
public class RuntimeStat
{
    public int BaseValue;
    public int AdditiveModifier;
    public float MultiplicativeModifier = 1f;

    public int FinalValue =>
        Mathf.Max(0, Mathf.RoundToInt((BaseValue + AdditiveModifier) * MultiplicativeModifier));
}
```

```
→ Before Damage Trigger
→ 기본피해 × 치명 × Weak
→ DEF 차감 (IgnoreDefense 시 생략)
→ × Vulnerable
→ 내림, 최소 1 (공격 피해. 상태이상 틱은 스택 값 그대로) — 정본 `01` D-01
→ Shield 감소 (IgnoreShield 시 생략)
→ HP 감소
→ OnDamageTaken Trigger
→ HP <= 0 → IsDead, Death Queue 등록
→ After Damage Trigger
```

## 17. QueueProcessor 상세 흐름

### 전체 처리 흐름

```
Enqueue Main Action
→ Main Action Execute
→ Flush Death Queue
→ Flush Trigger Queue (Trigger마다 Death 재-Flush)
→ 다음 Main Action
→ (Main 비면) 최종 Death Flush
```

### QueueProcessor 의사 코드

```csharp
public class QueueProcessor
{
    public void Process()
    {
        while (mainQueue.Count > 0)
        {
            ExecuteMainAction();
            FlushDeathQueue();
            FlushTriggerQueue();
        }
        FlushDeathQueue();
    }
}
```

### Trigger Depth 초과 시 처리

```
MaxTriggerDepth = 32
MaxTriggerIterationsPerFlush = 20
초과 시 → 전투 중단 → 로그 출력 → Emergency Cleanup
```

### Queue 안정성 규칙

| 규칙 | 설명 |
|---|---|
| Queue 내부 직접 수정 금지 | Action만 허용 |
| Resolve 중 입력 금지 | MainPhase 외 금지 |
| Death 즉시 제거 금지 | `IsDead` + Death Queue 필수 |
| Trigger 직접 실행 금지 | TriggerQueue 사용 |
| 난수 | `BattleRandom`만 사용 |

## 18. CardResolver 구조

## 19. StatusSystem 상세 규칙

### 처리 순서


| Bind | 공격/스킬 차단, 희생/상태이상 허용 |
