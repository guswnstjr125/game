> **문서 역할**: 카드 98장(드롭 92장 + 융합 전용 6장)을 `CardResolver`에 바로 연결할 수 있는 규칙/키/파라미터 확정
> **참조 문서**: 17_카드_데이터베이스, 06_전투_코어_상세설계

## 1. CardResolver 표준 스키마

| 필드 | 설명 | 예시 |
|---|---|---|
| CardId | 카드 고유 ID | `NEC_ACT_003` |
| ResolverKey | 실행 핸들러 키 | `ACT_NEC_DEATH_WHIRL` |
| ActionBundle | Queue에 넣을 액션 묶음 | `Damage+Heal` |
| TargetRule | 타겟 선택 규칙 | `FrontEnemy`, `AllEnemies`, `SelectedAlly` |
| Params | 수치 파라미터 | `{Damage:15, HealRatio:0.5}` |

### 1.1 효과 Resolver (구 `05` §18에서 옮김)

CardResolver는 카드 효과를 `EffectDefinition`으로 바꾸고, 효과 종류별 Resolver가 BattleAction 목록을 만들어 Queue에 넣는다. 직접 상태를 바꾸지 않는다 (`05` §1 Rule 4). 생성 경로는 Trigger와 같은 `ActionFactory`다 (`08` §6).

```csharp
public interface IEffectResolver
{
    List<BattleAction> Resolve(EffectDefinition effect, RuntimeUnit source, RuntimeUnit target);
}
```

| Resolver | 역할 |
|---|---|
| DamageResolver | 피해 |
| HealResolver | 회복 |
| StatusResolver | 상태이상 부여·해제 |
| DrawResolver | 드로우·버리기 |
| SummonResolver | 소환·토큰 |
| SacrificeResolver | 희생 |

강화된 카드는 `Cards_Upgrade.Up_Params`의 키 값으로 Params를 덮어쓴 뒤 Resolver에 넘긴다 (`38` §4).

## 2. Monster 카드(56장) 매핑 규칙

- 공통 ResolverKey: `MON_SUMMON`
- 공통 ActionBundle: `SpawnRuntimeMonster(CardId) + OnSummonEffect(CardId)`
- 스탯은 카드 DB(HP/ATK/DEF/Crystal) 그대로 사용
- `OnSummonEffect`는 아래 `MON_EFFECT_KEY`로 분기

| CardId 패턴 | MON_EFFECT_KEY |
|---|---|
| `*_MON_*` 효과 없음 | `NONE` |
| Deathrattle 보유 | `DEATHRATTLE_*` |
| 소환 시 상태이상/드로우/소환 | `ON_SUMMON_*` |
| 공격 특수(다중타·처형) | `ON_ATTACK_*` |

## 5. CardId→ResolverKey 자동 규칙

```txt
if CardId contains "_MON_" -> MON_SUMMON
if CardId contains "_SKL_" -> SKL_{CLASS}_{lookup}
if CardId contains "_ACT_" -> ACT_{CLASS}_{lookup}
```

- `lookup`은 위 표의 `CardId` 기준 정확 매핑
- 런타임에는 `Dictionary<string, ResolverSpec>`로 로딩
